# 클로드 코드 작업 효율성 평가 및 자동화 계획서

## 0. 평가 범위와 한계 (먼저 밝힘)

- 이 계획서를 작성하는 세션은 **격리된 클라우드 컨테이너**에서 실행되며, 오직 이 저장소(`eyu74368-boop/-`) 하나에만 접근 권한이 있습니다.
- 따라서 사용자 PC에서 동시에 돌아가는 "다른 모든 클로드 코드 세션"의 실시간 작업 로그, 다른 로컬 저장소, 터미널 히스토리는 직접 확인할 수 없습니다.
- 이 계획서는 (1) **이 저장소/세션에서 관찰 가능한 사실**과 (2) **Claude Code의 일반적인 효율화 기법(공식 스킬/도구 기준)**을 근거로 작성했습니다. 다른 PC의 실제 세션들을 비교 분석하려면 각 세션에서 이와 같은 진단을 개별 실행하거나, 작업 로그를 이 저장소에 공유해 주셔야 정확한 비교가 가능합니다.

### 목표 재정의

이 계획서의 목적은 단순히 "작업량 줄이기"가 아니라 **① 토큰 사용 효율화**와 **② 결과물 품질의 유지·상승**을 동시에 달성하는 것입니다. 두 목표가 충돌할 경우(예: 탐색/검증을 생략하면 토큰은 줄지만 품질이 떨어짐), **품질을 지키는 선에서 "낭비되는" 토큰만 제거**하는 것을 원칙으로 합니다. 낭비되는 토큰 = 같은 결과를 위해 불필요하게 반복되는 탐색·재확인·재작업이며, 필요한 탐색·검증·테스트는 낭비가 아닙니다.

## 1. 현재 저장소 현황

| 항목 | 내용 |
|---|---|
| 커밋 수 | 2개 (`클로드 코드 전역 설치 가이드 추가`, `[docs] CLAUDE.md 추가`) |
| 파일 구성 | `README.md`(설치 가이드), `CLAUDE.md`(운영 매뉴얼) |
| 실제 구현 코드 | 없음 (근무표 생성, 계량기 이미지 인식 등 도메인 코드 미착수) |

**진단**: 규칙(CLAUDE.md)은 상세하게 정의되어 있으나, 이를 실행할 실제 자동화 스크립트가 아직 없습니다. "계획만 있고 실행 자산이 없는" 상태 자체가 현재 가장 큰 비효율 요인입니다.

## 2. 일반적인 비효율 요인 진단 및 자동화 가능 여부

| 비효율 요인 | 원인 | 자동화/전환 가능 여부 |
|---|---|---|
| 파일 수정마다 반복 승인 프롬프트 | 기본 권한 모드가 매번 확인을 요구 | **가능** — `fewer-permission-prompts` 스킬로 반복되는 읽기 전용/저위험 명령을 `.claude/settings.json` allowlist에 등록해 절감 |
| 반복적인 상태 점검(빌드/배포/PR 확인) | 사람이 수동으로 재요청 | **가능** — `/loop` 스킬로 주기적 자동 점검, PR은 `subscribe_pr_activity`로 이벤트 기반 자동 감시 |
| 매 세션 컨텍스트 재설명 | 프로젝트 배경을 매번 다시 설명 | **이미 해결됨** — CLAUDE.md가 이 역할을 수행 중 (좋은 패턴, 유지 권장) |
| 엑셀 근무표 생성 반복 수작업 | 코드 미구현, 수기 반복 | **자동화 필요** — `pandas`/`openpyxl` 기반 스크립트로 전환 가능 (미착수) |
| 수도계량기 이미지 인식 반복 수작업 | 코드 미구현 | **자동화 필요** — `OpenCV` 기반 배치 처리 파이프라인으로 전환 가능 (미착수) |
| 단발성 대형 작업을 순차 처리 | 서브에이전트 미활용 | **가능** — 독립적인 조사/검증 작업은 `Agent`(서브에이전트)로 병렬 위임 가능 |

## 3. 다른 기능/도구로 전환 가능 여부

- **권한 최소화**: 매 사용마다 안전이 검증된 명령(예: 읽기 전용 조회)은 승인 없이 자동 실행되도록 `settings.json`에 등록 — 전환 가능, 파괴적이지 않음.
- **예약/반복 실행**: 정기 점검(예: 매일 아침 재고/센서 데이터 체크)이 필요하다면 `/loop` 또는 크론 기반 트리거로 전환 가능.
- **멀티 에이전트 오케스트레이션(Workflow)**: 대규모 반복 작업(예: 여러 지역의 계량기 이미지를 동시에 분류)이 생기면 `Workflow` 도구로 전환 가능하나, **사용자가 명시적으로 동의("워크플로 사용해줘" 등)한 경우에만** 사용 — 임의 전환 금지.
- **로컬 vs 클라우드 세션 분리**: 반복적이고 장시간 걸리는 배치 작업(이미지 대량 처리 등)은 클라우드 세션(Claude Code on the web)으로 옮겨 로컬 PC 자원 점유 없이 처리하는 것도 검토 가능.

## 4. 본인(현재 에이전트)의 "분신"/기능화 가능성 자체 평가

- **가능한 것**: `Agent` 툴로 독립적인 하위 작업(코드 탐색, 리서치, 검증)을 서브에이전트에 위임해 병렬 처리할 수 있습니다. 예: 근무표 생성 로직과 이미지 인식 로직을 동시에 개발할 때 각각을 서브에이전트에 맡기고 저는 통합/검토를 담당하는 방식.
- **가능하지만 신중해야 하는 것**: `Workflow` 툴로 다수 에이전트를 오케스트레이션하는 것은 토큰 소모가 크므로, 사용자가 명시적으로 요청한 경우에만 사용합니다(임의 판단 금지).
- **현재 판단**: 이 저장소는 아직 실질적인 코드/작업량이 거의 없어 분신·병렬화로 얻을 이득이 크지 않습니다. **1) 근무표 자동화, 2) 계량기 이미지 인식 파이프라인**처럼 서로 독립적인 모듈이 실제로 만들어지기 시작하면, 그 시점에 서브에이전트 병렬 개발이 유효합니다.

## 5. 토큰 사용 효율화 ↔ 품질 유지 전략

토큰을 줄이는 방법과 품질을 지키는 방법을 대립시키지 않고, **"중복/재작업 제거"**와 **"검증 단계 유지"**를 짝지어 적용합니다.

| 구분 | 토큰 절감 방법 | 품질 유지 장치 |
|---|---|---|
| 컨텍스트 관리 | CLAUDE.md/시스템 규칙을 간결하게 유지 — 매 세션 반복 전송되는 지시문 분량을 최소화 | 규칙 삭제가 아니라 **압축**(중복 문장 제거, 예시 통합)만 수행, 의미 누락 여부 재검토 |
| 탐색 | 넓은 탐색(파일 다수 열람, 전체 저장소 훑기)은 `Explore`/`general-purpose` 서브에이전트에 위임해 메인 컨텍스트에는 결과 요약만 남김 | 탐색 생략이 아니라 **위치 이전** — 필요한 탐색은 그대로 수행하되 소비 위치만 분리 |
| 재조회 방지 | 이미 읽었거나 방금 수정한 파일을 다시 Read로 확인하지 않음 (Edit/Write 실패 시에만 오류로 알 수 있음을 신뢰) | 대신 자동 검증 도구(테스트, 타입체크, 린트)로 결과를 확인 — "눈으로 재확인" 대신 "도구로 검증" |
| 도구 호출 | 서로 독립적인 조회는 한 번에 병렬 호출해 왕복 횟수 절감 | 의존관계가 있는 호출은 병렬화하지 않고 순차 실행 유지 (정확성 우선) |
| 산출물 | 요청하지 않은 문서·설명·예제코드 생성을 자제 (본 계획서처럼 명시적으로 요청된 것만 작성) | 대신 요청된 산출물은 검토·수정(Edit) 위주로 다뤄 처음부터 다시 쓰는 재작업을 줄임 |
| 병렬화/서브에이전트 | 독립적인 대형 작업(예: 근무표 자동화 + 이미지 인식 파이프라인)만 서브에이전트로 분리 — 작은 작업까지 쪼개면 오히려 조율 비용(토큰)이 늘어남 | 서브에이전트 결과는 반드시 통합 단계에서 한 번 더 일관성 검토 |
| 재작업 방지(최대 낭비 요인) | 작은 단위로 커밋·검증하며 진행해 뒤늦게 큰 재작업이 발생하지 않도록 함 | 파괴적 변경 전 계획서/승인 절차(CLAUDE.md 3항)를 유지 — 승인 없이 진행했다가 되돌리는 것이 가장 큰 토큰 낭비 |

**하지 않을 것(품질 저하로 이어지는 절감은 배제)**: 예외 처리 생략, 테스트/검증 생략, 사용자 승인 없는 대규모 변경, 코드 리뷰·보안 리뷰 스킵.

## 6. 실행 계획 (승인 대기 — 아직 실행하지 않음)

1. **권한 설정 정비**: `fewer-permission-prompts` 스킬로 반복 확인이 필요한 안전한 명령을 `.claude/settings.json`에 등록 (비파괴적)
2. **도메인 스크립트 스켈레톤 작성**: `scripts/근무표_생성.py`(pandas/openpyxl), `scripts/계량기_이미지_인식.py`(OpenCV) 뼈대 작성 — CLAUDE.md 규칙(PEP8, 한국어 독스트링, 예외 처리)을 준수
3. **반복 점검 자동화**: 필요 시 `/loop`로 정기 작업 등록
4. **필요 시에만 Workflow 도입**: 실제 병렬 처리가 필요한 대규모 작업이 생기면 사용자 동의 하에 적용
5. **CLAUDE.md 경량화 검토**: 현재 CLAUDE.md 분량과 반복도를 점검해, 의미 손실 없이 압축 가능한 부분이 있는지 별도로 검토·제안 (승인 후 적용)

> CLAUDE.md 3항 규칙에 따라, 위 1~5단계 중 실제 코드를 새로 작성/삭제하는 파괴적 성격의 단계(2, 3, 4, 5)는 사용자 승인 후 진행합니다. 이 문서는 그 승인을 받기 위한 계획서입니다.
